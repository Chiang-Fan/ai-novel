## 🎯 核心功能

### 1️⃣ **版本管理** 📚

#### 创建版本
```
手动创建:
├─ 版本标签（可选）
├─ 版本备注（可选）
├─ 自动版本号递增
└─ 自动设为当前版本

自动创建类型:
├─ MANUAL - 手动创建
├─ AUTO_SAVE - 自动保存
├─ AUTO_SNAPSHOT - 自动快照
└─ ROLLBACK - 版本回滚
```

#### 版本列表
```
显示内容:
├─ 版本号（v1, v2, ...）
├─ 版本标签
├─ 字数统计
├─ 创建时间
├─ 当前标识
└─ 操作菜单

排序: 按版本号降序（最新在前）
```

### 2️⃣ **版本对比** 🔍

#### 差异算法
```
使用 LCS（最长公共子序列）算法:
1. 按行分割文本
2. 构建 DP 表
3. 回溯生成差异
4. 标记类型: EQUAL/INSERT/DELETE
```

#### 对比展示
```
统计信息:
├─ +新增行数（绿色）
├─ -删除行数（红色）
├─ ~修改行数（黄色）
├─ =未变化行数（灰色）
└─ 字数差异

详细差异:
├─ 绿底显示新增内容
├─ 红底显示删除内容
├─ 白底显示未变化内容
└─ 行号对齐显示
```

### 3️⃣ **版本操作** 🛠️

#### 回滚功能
- 选择任意历史版本
- 创建新版本（内容同历史版本）
- 保留完整历史记录
- 不影响原版本

#### 标签管理
- 编辑版本标签
- 添加版本备注
- 快速识别版本
- 方便查找定位

#### 删除功能
- 软删除（标记删除）
- 保护当前版本
- 可恢复设计（未来）
- 确认对话框保护

### 4️⃣ **统计分析** 📊

#### 版本统计
```
基础统计:
├─ 总版本数
├─ 当前版本号
└─ 总编辑次数

字数变化:
├─ 总增加字数
├─ 总删除字数
└─ 平均编辑大小

编辑习惯:
└─ 最活跃编辑时段（未来）
```

## 🗄️ **数据库设计**

### chapter_versions（版本表）
```sql
字段（13个）:
├─ id (主键)
├─ chapter_id (外键 → chapters)
├─ version_number (版本号)
├─ content (版本内容, LONGTEXT)
├─ word_count (字数)
├─ version_tag (版本标签)
├─ version_note (版本备注)
├─ created_by (创建者)
├─ created_type (创建类型)
├─ is_current (是否当前版本)
├─ is_deleted (是否已删除)
└─ created_at (创建时间)

索引（4个）:
- chapter_id, version_number, created_at, is_current
```

### version_comparisons（对比缓存表）
```sql
字段（7个）:
├─ id (主键)
├─ version_id_from (源版本ID)
├─ version_id_to (目标版本ID)
├─ diff_result (差异结果 JSON, LONGTEXT)
├─ added_count (新增行数)
├─ deleted_count (删除行数)
└─ modified_count (修改行数)

索引（1个）:
- (version_id_from, version_id_to)
```

## 🚀 **使用场景**

### 场景 1：创作迭代
```
作家思路:
"我对第 15 章不太满意，想改改..."

操作流程:
1. 在版本管理中查看当前版本
2. 创建新版本（标签: "优化第二幕冲突"）
3. 修改内容
4. 如果不满意，回滚到之前的版本
5. 或者对比两个版本，选择最佳部分
```

### 场景 2：A/B 测试
```
写作需求:
"两种不同的结局，不知道哪个更好..."

操作流程:
1. 版本 v8: 结局 A（悲剧）
2. 版本 v9: 结局 B（喜剧）
3. 使用对比功能查看差异
4. 邀请读者反馈
5. 根据反馈选择最终版本
```

### 场景 3：版本追溯
```
问题场景:
"上周的那个情节转折很好，现在找不到了..."

操作流程:
1. 打开版本管理
2. 按时间筛选上周的版本
3. 查看版本列表（带标签）
4. 找到目标版本
5. 复制需要的内容或直接回滚
```
