# API路由与调用修复报告

## 📋 问题概述

用户报告了两个关键问题：
1. **伏笔自动检测失败** - `No static resource api/plot-hooks/detect/2/1`
2. **加载数据失败** - `Failed to convert value of type 'java.lang.String' to required type 'java.lang.Long'; For input string: "templates"`

## 🔍 问题诊断

### 问题1：伏笔检测API不匹配

**前端调用**：
```javascript
// ai-novel/src/main/frontend/src/api/index.js:178
detectFromChapter: (novelId, chapterNumber) => api.post(`/plot-hooks/detect/${novelId}/${chapterNumber}`)
```

**后端定义（修复前）**：
```java
@PostMapping("/detect/{chapterId}")
public ResponseEntity<ApiResponse<List<PlotHookDto>>> detectHooks(@PathVariable Long chapterId)
```

❌ **问题**：前端传递 `novelId + chapterNumber`，后端只接受 `chapterId`

---

### 问题2：路由优先级冲突

**错误日志**：
```
Could not resolve parameter [0] in 
public ApiResponse<WritingStyleResponse> WritingStyleController.getStyle(java.lang.Long): 
Failed to convert value of type 'java.lang.String' to required type 'java.lang.Long'; 
For input string: "templates"
```

**根本原因**：
```java
@RestController
@RequestMapping("/api/writing-styles")
public class WritingStyleController {
    
    // ❌ 这个方法会匹配所有路径，包括 /templates
    @GetMapping("/{id}")
    public ApiResponse<WritingStyleResponse> getStyle(@PathVariable Long id)
    
    // ❌ 没有 /templates 端点，但前端在调用
}
```

前端调用 `/api/writing-styles/templates` 时，Spring MVC将 `templates` 匹配到 `/{id}` 路径，尝试转换为Long类型失败。

---

## ✅ 修复方案

### 修复1：伏笔检测API统一

#### 1.1 更新后端Controller

```java
// PlotHookController.java
@PostMapping("/detect/{novelId}/{chapterNumber}")
@Operation(summary = "AI 自动检测伏笔", description = "使用 AI 分析章节内容，自动识别潜在伏笔")
public ResponseEntity<ApiResponse<List<PlotHookDto>>> detectHooks(
        @PathVariable Long novelId,
        @PathVariable Integer chapterNumber) {
    log.info("开始检测小说 {} 第 {} 章的伏笔", novelId, chapterNumber);
    List<PlotHookDto> hooks = plotHookService.detectPlotHooksByChapterNumber(novelId, chapterNumber);
    return ResponseEntity.ok(ApiResponse.success("检测成功", hooks));
}
```

#### 1.2 添加Service方法

```java
// PlotHookService.java
/**
 * AI 自动检测章节中的伏笔（通过小说ID和章节号）
 */
@Transactional
public List<PlotHookDto> detectPlotHooksByChapterNumber(Long novelId, Integer chapterNumber) {
    Chapter chapter = chapterRepository.findByNovelIdAndChapterNumber(novelId, chapterNumber)
        .orElseThrow(() -> new RuntimeException("章节不存在: 小说ID=" + novelId + ", 章节号=" + chapterNumber));
    
    return detectPlotHooks(chapter.getId());
}
```

#### 1.3 添加Repository方法

```java
// ChapterRepository.java
/**
 * 根据小说ID和章节号查询章节
 */
Optional<Chapter> findByNovelIdAndChapterNumber(Long novelId, Integer chapterNumber);
```

## 🎯 关键经验总结

### 1. Spring MVC路由匹配规则

```java
// ❌ 错误：宽泛路径在前
@GetMapping("/{id}")          // 会匹配 /templates
@GetMapping("/templates")     // 永远不会被调用

// ✅ 正确：具体路径在前
@GetMapping("/templates")     // 先匹配具体路径
@GetMapping("/{id}")          // 兜底匹配其他路径
```

**原则**：
- 更具体的路径模式应该定义在更通用的路径模式之前
- 使用 `@Order` 注解无法改变同一个Controller内的匹配顺序
- 考虑使用正则表达式限制路径变量：`@GetMapping("/{id:\\d+}")`

---

### 2. API设计一致性

| 错误模式 | 正确模式 |
|---------|---------|
| 前后端参数不一致 | 明确API契约，前后端统一 |
| 使用实体ID传递 | 使用业务ID组合（更符合REST） |
| 缺少必要的Repository方法 | 提前检查依赖方法是否存在 |

---

### 3. 错误排查技巧

```bash
# 1. 搜索错误日志中的关键信息
grep -r "For input string.*templates" startup.log

# 2. 定位具体的Controller和方法
# 错误日志会显示：
# "Could not resolve parameter [0] in 
#  public ApiResponse<WritingStyleResponse> 
#  WritingStyleController.getStyle(java.lang.Long)"

# 3. 检查路由定义顺序
# 查看 @GetMapping 定义的先后顺序
```
