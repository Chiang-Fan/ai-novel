## 技术架构概览

### 后端架构
```
Controller层 (21个)
    ↓
Service层 (30+个)
    ├─ BusinessService (核心业务)
    ├─ AiService (AI集成)
    └─ ConstraintService (约束引擎)
    ↓
Repository层 (44个数据表)
    ↓
Entity层 (数据模型)
    ↓
MySQL 8.0数据库
```

### 前端架构
```
页面层 (22个路由)
    ↓
组件层 (35+个Vue组件)
    ├─ 通用组件 (Button, Input, Modal等)
    ├─ 业务组件 (OutlineEditor, SceneDialog等)
    └─ 面板组件 (SmartWriting, Analysis等)
    ↓
状态管理 (Pinia Store)
    ↓
API层 (客户端请求)
```

### AI集成架构
```
通义千问 API (v2.12.0)
    ↓
AiService (封装和调用)
    ├─ chat() - 文本生成
    ├─ chatJson() - JSON响应
    └─ 流式处理
    ↓
业务Service (场景应用)
    ├─ 推荐生成
    ├─ 约束验证
    ├─ 续写增强
    └─ 描写优化
```

## 风险管理

### 高风险项
1. **AI API稳定性** - 依赖第三方服务
   - 缓解: 实现降级方案和重试机制
   
2. **数据库性能** - 随着数据增长可能变慢
   - 缓解: 合理使用索引, 分表分库规划
   
3. **前后端集成** - 接口契约变化
   - 缓解: 版本管理, API文档同步

### 中风险项
1. **AI约束规则准确性**
   - 缓解: 用户反馈和持续优化
   
2. **复杂世界观结构**
   - 缓解: JSON灵活存储, 早期用户测试
